# Implement portable solo-dev work-intake workflow expansion

User approved starting research, implementation, testing, failure-path validation, role-play audits, and real-work exercise for a Work Intake expansion. Requirements: keep the workflow usable for other projects; separate reusable workflow mechanics from project-specific data/policy; capture user intent slices and lead-interpreted work slices without enterprise documentation burden; present records visually in the existing guide using trace graphs or similar views; research whether external trackers such as GitHub Issues should be canonical or optional; test each subsystem deeply, including failure paths and workflow trace quality; audit for hangs and brittle one-off docs; then use the workflow on real pending work and review both result and trace.
