What This Is

This is the public-safe guide for the Nexus Codex workflow. The complete internal workflow system lives in the repository under .codex/, with the compact handover at .codex/workflow/current-state.md.

The old Claude Code setup is archived in the repo and is no longer active.

Workflow Shape

Lead

Plans, routes, integrates, records state, and owns final quality.

Spark Worker

Only narrow, explicit, testable coding slices. Must escalate when scope or reasoning gets hard.

Strong Worker

GPT-5.5 class coding for ambiguous debugging, architecture, cross-cutting changes, visual/design judgment, and Spark fallback.

Review/Audit

Focused checks against project patterns, related updates, deprecated approaches, and deployment evidence.

How Future Sessions Resume

  • Read WORKFLOW.md, AGENTS.md, then .codex/workflow/current-state.md.
  • Use the canonical ladder: npm run workflow:status, npm run workflow:health, npm run workflow:release-gate, npm run workflow:deployed-gate.
  • Use trusted Custom (config.toml) when project hooks matter. Full access grants permissions but does not prove hooks/config loaded; diagnose with npm run workflow:hook-runtime-check and bootstrap new projects from .codex/workflow/templates/project-bootstrap.md.
  • Use detailed records under .codex/workflow/records/ instead of loading chat transcripts.

Branch Closeout

Worktree records are interim evidence. Branches close with branch-scope records tied to the current branch hash.

node .codex/scripts/nexus-workflow.mjs record-patch --scope branch --summary "<branch summary>" --worker codex-lead
node .codex/scripts/nexus-workflow.mjs record-review --scope branch --kind general --verdict pass --reviewer <name> --notes "<summary>"
node .codex/scripts/nexus-workflow.mjs record-verify --scope branch --verdict pass --verifier <name> --commands "<timed-command-ids>" --notes "<commands/results>"
node .codex/scripts/nexus-workflow.mjs record-audit --scope branch --verdict pass --auditor <name> --commands "<timed-command-ids>" --notes "<summary>"

Add focused branch review kinds such as workflow, design, or integrated when the release gate asks for them.
