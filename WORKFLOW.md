# Nexus Workflow Entry Point

The active AI/human workflow lives under `.codex/`.

- Start here: `.codex/README.md`
- Current state: `.codex/workflow/current-state.md`
- Original long-running request: `.codex/workflow/briefs/2026-05-09-original-user-brief.md`
- Project patterns: `.codex/knowledge/`
- Workflow profile and policy: `.codex/workflow/profile.json` and `.codex/workflow/policy/*.json`
- Structured records: `.codex/workflow/records/`
- Work Intake guide: `.codex/knowledge/work-intake.md`
- Visual dashboard/wiki: `.codex/dashboard/index.html` generated by `npm run workflow:dashboard`
- Public-safe guide URL: `https://cv.rehou.games/nexus/workflow/` generated by `npm run workflow:public-guide`
- Bootstrap template for this workflow in another project: `.codex/workflow/templates/project-bootstrap.md`

For non-trivial product, bug, workflow, or design requests, capture compact Work Intake records before or during implementation:

```bash
node .codex/scripts/nexus-workflow.mjs record-intent --kind feature --status captured --summary "<compact user intent>"
node .codex/scripts/nexus-workflow.mjs record-work-slice --intent <INTENT-id> --status active --summary "<lead interpretation>" --acceptance "<done signals>"
```

Link substantive evidence records with `--work-slice <WORK-SLICE-id>` and diagnose trace gaps with:

```bash
npm run workflow:work-intake-check
```

Before branch release, close each current slice with a new append-only record:

```bash
node .codex/scripts/nexus-workflow.mjs close-work-slice --slice <WORK-SLICE-id> --status done --notes "<evidence complete>"
```

The generated guide shows the Inbox, Active Slices, Intent Trace Graph, Feature Catalog, and Warnings from those records.

Recommended Codex UI mode for this project is `Custom (config.toml)` after trusting the project. That reads `.codex/config.toml`, keeps the same no-prompt posture as Full access, and enables project hooks. Full access alone grants permissions for the current session; it does not prove that project config or hooks were loaded.

Canonical execution ladder:

1. `npm run workflow:status`
2. `npm run workflow:health` when diagnosis is needed
3. `npm run workflow:release-gate`
4. `npm run workflow:deployed-gate` after server validation

The old Claude Code setup is historical evidence only. Active Codex guidance is in `AGENTS.md`, `.codex/`, and `.agents/skills/`. Reusable workflow mechanics live in `.codex/scripts/workflow-engine.mjs`; Nexus-specific facts live in the profile and policy pack.

Diagnostics for the workflow system itself:

- `npm run workflow:inventory-check` verifies the `.codex/` tree has no misplaced active, legacy, runtime, or unmanaged artifact files.
- `npm run workflow:policy-check` verifies the policy pack is loaded and consumed by scripts, docs, file classifiers, and package commands.
- `npm run workflow:trace-check` verifies command-run telemetry is well formed so execution time, warnings, failures, and timeouts remain auditable.
